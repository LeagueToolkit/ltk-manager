# Implementation Plan: LTK Protocol Install List

**Branch**: `002-ltk-protocol-install-list` | **Date**: 2026-11-02 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `.specify/specs/002-ltk-protocol-install-list/spec.md`

## Summary

Add an `ltk://install-list` route beside `ltk://install`. The link carries a manifest URL; the
manager fetches the manifest within its limits, shows one dialog for the list, and installs the
checked items one after another, minting each download link just before its download. Each mod
the run touches records its origin, so a second run skips what is current. The list's mods end
at the front of the load order in the list's order.

## Technical Context

**Language/Version**: Rust (stable, edition 2024 in the crates, 2021 in `src-tauri`) + TypeScript
**Primary Dependencies**: `reqwest` (blocking), `serde_json`, existing deep-link plumbing,
TanStack Query, Zustand
**Storage**: `library.json` gains an optional `origin` per mod entry
**Testing**: `cargo test -p ltk-manager-core deep_link`, `vitest run src/modules/deep-link`
**Target Platform**: Windows, as the protocol itself
**Constraints**: One item at a time; same-host downloads; 1 MiB / 10 s / 500 items; the run
holds one command for its whole length
**Scale/Scope**: One route, one core module, one library field and method, one event, three
commands, one dialog

**Structure Decision**: The route, the manifest and the mint sit in core beside the single
install's download, because they are the protocol. The run sits in `src-tauri` beside the single
install's command, because it needs the library, the settings and the patcher together. The
origin record sits in the library, because it is a fact about a mod.
